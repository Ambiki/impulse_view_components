Autocomplete API ​

js
const autocomplete = document.querySelector('awc-autocomplete');

TypeScript ​

The selection mode (single vs. multiple) determines the type of value and the arguments removeValue accepts, and the source (local vs. ajax) determines whether setValue requires the text argument. TypeScript resolves these automatically when you narrow on the multiple and ajax properties:

ts
const autocomplete = document.querySelector('awc-autocomplete')!;

if (autocomplete.multiple) {
  autocomplete.value; // string[]
  autocomplete.removeValue('1'); // value argument is required
} else {
  autocomplete.value; // string
  autocomplete.removeValue(); // no argument
}

if (autocomplete.ajax) {
  autocomplete.setValue('1', 'One'); // text is required
} else {
  autocomplete.setValue('1'); // text is optional
}

If you already know the mode at the call site, pass the exported type to querySelector instead of narrowing:

ts
import type {
  MultipleAutocompleteElement,
  SingleAutocompleteElement,
} from '@ambiki/impulse-view-components/autocomplete';

const multi = document.querySelector<MultipleAutocompleteElement>('awc-autocomplete')!;
multi.value; // string[]

const single = document.querySelector<SingleAutocompleteElement>('awc-autocomplete')!;
single.value; // string

If you already know the source at the call site, you can also pass the exported type to querySelector instead of narrowing on ajax:

ts
import type {
  AjaxAutocompleteElement,
  LocalAutocompleteElement,
} from '@ambiki/impulse-view-components/autocomplete';

const ajax = document.querySelector<AjaxAutocompleteElement>('awc-autocomplete')!;
ajax.setValue('1', 'One'); // text is required
ajax.setValue('1'); // ✗ type error

const local = document.querySelector<LocalAutocompleteElement>('awc-autocomplete')!;
local.setValue('1'); // text is optional

Each alias leaves the other dimension open, but they are composable — pass the other dimension as a type argument to pin both at once:

ts
const el = document.querySelector<MultipleAutocompleteElement<'ajax'>>('awc-autocomplete')!;
el.value; // string[]
el.setValue('1', 'One'); // text is required

// `AjaxAutocompleteElement<'multiple'>` resolves to the same type.

Properties ​

open ​

Whether the listbox is open. Setting it, or adding or removing the open attribute, shows or hides the listbox as show and hide do. A removed autocomplete keeps open, and opens its listbox again when it's added back.

js
autocomplete.open;
// => false
autocomplete.open = true;

value ​

The selected value(s). For a single select this is a string; for a multiple select it is a string[].

js
// Multiple select
autocomplete.value;
// => ['1', '2']

// Single select
autocomplete.value;
// => '1'

multiple ​

Whether multiple values can be selected. Narrowing on this resolves mode-dependent types — see TypeScript.

js
autocomplete.multiple;
// => true

ajax ​

Whether the options are fetched from the server (i.e. the src attribute is set). Narrowing on this resolves source-dependent types — see TypeScript.

js
autocomplete.ajax;
// => true

activeOption ​

The option that has the data-active attribute.

js
autocomplete.activeOption;

visibleOptions ​

All the visible options of the autocomplete element.

js
autocomplete.visibleOptions;

options ​

All the options of the autocomplete element.

js
autocomplete.options;

form ​

The parent form element.

js
autocomplete.form;

Methods ​

show ​

Shows the listbox. Emits awc-autocomplete:shown, but not the cancelable awc-autocomplete:show.

js
autocomplete.show();

hide ​

Hides the listbox. Emits awc-autocomplete:hidden, but not the cancelable awc-autocomplete:hide.

js
await autocomplete.hide();

requestShow ​

Shows the listbox as if the user asked to. Emits a cancelable awc-autocomplete:show, and does nothing if it is prevented.

js
autocomplete.requestShow();

requestHide ​

Hides the listbox as if the user asked to. Emits a cancelable awc-autocomplete:hide, and does nothing if it is prevented.

js
await autocomplete.requestHide();

setValue ​

Sets the value of the element. When the options are fetched from the server, the text argument is required (the option is not in the DOM, so its text cannot be derived); for local options it is optional. See TypeScript for how to enforce this at compile time.

js
// Multiple select
autocomplete.setValue('apple', 'Apple');
autocomplete.value;
// => ['apple']

// When the options are not loaded from the server, you do not have to pass the text argument.
autocomplete.setValue('apple');
autocomplete.value;
// => ['apple']

removeValue ​

Removes a value from the element.

js
// Multiple select
autocomplete.removeValue('apple');
autocomplete.value;
// => []

TIP

The value argument is required for a multiple select and is not used by a single select (which clears its value when removeValue() is called). TypeScript enforces this when the mode is known — see TypeScript.

activate ​

Activates an option by setting the data-active attribute, and scrolls it into view. Pass { scroll: false } to skip the scrolling.

js
const option = autocomplete.options[0];
autocomplete.activate(option, { scroll: false });

deactivate ​

Deactivates the active option by removing the data-active attribute.

js
autocomplete.deactivate();

clear ​

Deselects all the selected options.

js
autocomplete.clear();

reset ​

Resets the autocomplete value to its initial state.

js
autocomplete.reset();

focus ​

Sets the focus on the input element. It also accepts the native focus options object.

js
autocomplete.focus({ preventScroll: true });

blur ​

Removes keyboard focus from the input element.

js
autocomplete.blur();

reposition ​

Positions the listbox straight away. Does nothing while the listbox is closed.

js
await autocomplete.reposition();

Events ​

Events work as they do on native elements. A user action (pressing the control or typing in the input, Escape, Alt+ArrowDown, Alt+ArrowUp, an outside click, the input losing focus, committing an option in a single select, clearing), or a requestShow or requestHide call, first emits a cancelable show or hide; calling preventDefault() on it keeps the listbox closed or open. show(), hide() and changing open act directly and emit no show or hide, and neither does closing because the form was reset. shown and hidden fire after every open and close. Connecting, moving and removing the element emit nothing.

Like the other events, show and hide bubble. A listener on an element that contains other autocompletes receives their show and hide too, so check event.target before preventing one.

Like input and change, commit, clear, remove and reset fire after the value has changed, and only when the user changed it or the form reset: setValue, removeValue, clear and reset called from code emit nothing.

commit reports the option's state after the commit in event.detail.selected: true when the commit selected it, false when it deselected it in a multiple select.

js
autocomplete.addEventListener('awc-autocomplete:commit', (event) => {
  const { value, selected } = event.detail;
  console.log(selected ? `Selected ${value}` : `Deselected ${value}`);
});

WARNING

In a single select, committing the option that is already selected emits commit with selected: true, although the value doesn't change. A future release will stop emitting it, as a native <select> emits no change when the user selects the option that is already selected (#310).
